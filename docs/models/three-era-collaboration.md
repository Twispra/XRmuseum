## 分支怎么走

`main` 继续服务当前可运行原型。模型资产汇总分支为 `codex/helmet-refinement-assets`，从已核对主线建立初始基准；成员认领具体工作后各开工作分支，PR 的 **base 指向资产汇总分支**，关联同一个 #25。经组员审阅后可汇总到该分支。一个 PR 合并不等于整体模型完成。

现有照片样件 [PR #28](https://github.com/Twispra/XRmuseum/pull/28) 保持 Draft，改为上述资产分支的候选成果；没有合并。未来如需将三个模型接入实际展览，再单独建立整合 Issue/PR 指向 main，处理交互绑定、剖面、材质、碰撞体和年代切换。当前不会自动把模型分支合到 main。

不要让六个人同时写资产汇总分支。各自任务分支保留贡献，汇总人按 PR 审阅收录；一个 `.blend` 同一时段一个写入者，各部件另存文件，由装配者汇总。更新主线时只在明确需要的情况下协调，不整份覆盖既有模型成果。

## 可以认领哪些工作

建议每个年代由两人协作；下面是六个可调整的工作包，不是已经给六位成员分配的任务，也不宣称任务难度完全相等。

| 可认领工作 | 负责的内容 | 首版交付 |
| --- | --- | --- |
| 早期头盔：资料与主体 | 明确具体实物，整理来源/外形比例，制作壳体及已核实的基础结构 | 来源与参数表、独立主体源文件、预览 |
| 早期头盔：细节与外观 | 与主体作者核对同一对象，制作可见窗件/配件，调整 UV/材质 | 独立细节源文件、原创或获许可材质、预览 |
| Mark V：资料与主体 | 核对既有资料的实际版本，制作壳体、基础连接结构等已核实部分 | 来源与参数表、独立主体源文件、预览 |
| Mark V：细节与外观 | 与主体作者核对版本，制作窗件及外部连接件，调整 UV/材质 | 独立细节源文件、材质、预览 |
| SuperLite 17B：资料与主体 | 收集同型号证据，确定比例，制作主体及已核实的基础结构 | 来源与参数表、独立主体源文件、预览 |
| SuperLite 17B：细节与外观 | 与主体作者核对版本，制作面窗/外部附件，调整 UV/材质 | 独立细节源文件、材质、预览 |

每对成员先共用同一参考对象和比例约定，然后各自编辑独立分件文件，互相审阅；一人被明确认领为最终装配文件的写入者。两边都参与来源核对、首版预览和导出检查，不能把整顶模型的最终整合/检查全留给其中一人。根据实际难度和进展再交换部分部件，不按人数或文件数机械计算公平。

也可认领更小的工作，如某一个窗件、一个型号的尺寸证据、对照图片标注或 UV 修正；写明实际产物和边界。先交能够审阅的首版，不要求一开始完成整顶模型。没有查清的内部结构不在任务中强行补出。

维护者核对评论中的文件重叠，更新 #25 的负责人和状态。共享源文件/最终装配需先确认写入者；认领留言并不是文件锁。两人不能因都留言“已认领”就同时编辑同一个 `.blend`。

### 认领后怎么开始

1. 先看原型/研究资料和具体来源；不会建模可先做可交付的资料核对或标注，在留言里说明。
2. 从资产汇总分支建立自己的任务分支，使用自己的 Git 身份。当前照片样件只在 PR #28；如要改该样件，从它的最新工作版本另开分支，声明依赖 #28，不复制旧原型生成器覆盖它。
3. 新文件放对应年代目录，按 `sources/parts/`、`references/`、`textures/`、`previews/`、`exports/`、`qa/` 区分。部件及资料文件带清楚名称，避免多人同时写总源文件/同一资料表。未知参数写“估算/待核实”。
4. 在 #25 发首版截图、对应 commit 和问题；需要修改的数据采纳后写回版本文件。
5. 用自己的 PR 提交实际成果，关联 #25，base 选择 `codex/helmet-refinement-assets`。写清文件、来源、修改、检查和未完成项；先汇总资产，不触碰主场景或 main。

资料任务也能通过 Markdown、图表或来源索引的 PR 留下实际贡献；只有留言、截图点赞或认领本身不能代替交付。检查可读源文件、导出、尺度/法线/UV/透明件与来源边界；未做的检查如实写未验证。

## 每个模型交付什么

- 可查资料与参数表：逐项记录来源、对应实物、可信度；把史料、照片观察、建模估算分开。
- 可编辑源文件和分件；FBX/GLB 导出、材质贴图、多角度预览、版本说明。
- 提前保留后续使用所需的分件名称、坐标/单位、前窗和连接点等定位说明；某个年代不存在的结构不能为复用功能而编造。
- 做资产检查：法线、开口/内壁、透明件、UV、导出尺度和重复打开。模型质量与来源检查完成后，再做运行时优化及整合验证。

## 小组怎样参与

**补资料**：在 #25 留言开头写模型名，再写 URL/页码、型号/实物、对应部件及参数；采用后写回版本文件。

**看模型**：从 #25 的查看入口进入工作 PR，展开 LFS 后查看 PNG、GLB 或 Blender；在 #25 反馈模型名、commit、视角和具体位置。查看不必认领写入权限。当前样件还在 PR #28 的工作分支，未进入资产汇总分支；只拉 main 或资产汇总分支看不到它。

**改模型**：在 #25 留言“我负责哪个模型/部件，修改哪些文件，使用哪个分支”，由维护者更新任务表；再从资产分支开个人分支。负责人未确定的工作不算已经分配或开工。一个人认领和独立分支仍按根 AGENTS 执行，不需要为每次认领另开 Issue。

**审阅汇总**：确认资料、外形、分件和导出后，PR 先进入资产分支。三个年代都达到可使用版本时，再讨论主项目接入；不以“成功导出”代替历史和外观审阅。

本次只调整管理与交接，不宣称完成另外两顶模型，不改现有运行时代码，也不自动给其他成员分配任务。

只有出现需要独立跟踪的实际阻碍或复杂问题时，才考虑额外 Issue。贡献记录保留在个人 commit/PR，Issue 数量不作为工作量。
