## 方法上刻意做的两个区分

1. **行为 ≠ 定性。** 自动产出的是 B1–B6 行为指标，**不是** RD/ST/TM/LG/RS/NV 定性码。
   "指了 4 次没按下"是事实；"因为以为悬停即选中"是解释，必须由主持人编码或访谈给出。
   两者在 issue log 里用 `source` 列分开（`telemetry` / `coded`），不混为一谈。
2. **不编造未测维度。** 没有观察到的东西不出现在结果里，不用"默认 0"假装测量。
   B4（求助）只在会话真正进入探索流程时判定；B5（按钮无效）只对 `*Button` 目标判定，
   避免把"点了热点但页面本来就该不变"误判成缺陷。

## 验证

**自测（13 项断言，合成夹具，不依赖 Unity 与真实数据）**：13/13 通过。

覆盖点：正常推进的会话不误报 B5；只有按钮动作且页面未变时才报 B5 且严重度为 4；
单目标 hover 不足 3 次不触发 B2；A→B→A 折返计数为 2 时触发 B3；
输出三个文件均可解析且行数正确。

**在 7 场真实自测会话上运行**（2026-11-17 22:09–23:06）：

| 指标 | 值 |
| --- | --- |
| 会话 | 7 |
| hover / activate / select | 30 / 4 / 0 |
| 每次 hover 对应 activate | 0.133 |
| 首次交互中位数 | 3.5 s |
| 推进到 Welcome 以外的会话 | 1 |

产出 3 条指标：B2「指得到但按不下去」（2 场，严重度 3，优先级 0.858）、
B3「在目标之间反复折返」（3 场，严重度 2，优先级 0.858）、
B1「整场没有任何交互」（1 场，严重度 3，优先级 0.429）。

**这些数字只证明工具能算对，不是评价结论** —— 输入是组员自测，`summary.md` 顶部已显式声明。
