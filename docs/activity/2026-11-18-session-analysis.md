## 方法上刻意做的两个区分

1. **行为 ≠ 定性。** 自动产出的是 B1–B6 行为指标，**不是** RD/ST/TM/LG/RS/NV 定性码。
   "指了 4 次没按下"是事实；"因为以为悬停即选中"是解释，必须由主持人编码或访谈给出。
   两者在 issue log 里用 `source` 列分开（`telemetry` / `coded`），不混为一谈。
2. **以有效快照判断页面。** B4 同时检查会话是否曾记录到有效的非 Welcome 页和求助次数。B5 以可明确换页的旧探索按钮及动作之后的快照为依据。实体站 Air/Voice 的 `select` 属于进入选择状态，确认或取消发生在释放阶段，缺少预期换页证据时在报告中标为待核查。

## 验证

在 Windows 使用 Python 3.12 运行 `python analyze_sessions.py --self-test`，27/27 项合成断言通过。
覆盖未知页、正常切换语言和折返、已识别的实体控件、动作后有效快照不足、人工编码 ID/严重度/成本校验、优先级舍入、同目标连续事件和三个输出。

**在 7 场真实自测会话上运行**（2026-11-17 22:09–23:06）：

| 指标 | 值 |
| --- | --- |
| 会话 | 7 |
| hover / activate / select | 30 / 4 / 0 |
| 每次 hover 对应 activate | 0.133 |
| 首次交互中位数 | 3.5 s |
| 曾观测到有效非 Welcome 页的会话 | 0 |

产出 3 条指标。B3「在目标之间反复折返」命中 4 场，严重度 2，优先级 1.143。B2「反复悬停且未记录选择或激活」命中 2 场，严重度 3，优先级 0.857。B1「会话未记录交互事件」命中 1 场，严重度 3，优先级 0.429。

**这些数字只证明工具能算对，不是评价结论** —— 输入是组员自测，`summary.md` 顶部已显式声明。
